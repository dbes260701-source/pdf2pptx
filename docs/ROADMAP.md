# 로드맵

두 외부 평가서(→ [EVALUATION-RESPONSE.md](EVALUATION-RESPONSE.md))에서 나온 항목 중
이번에 코드로 반영하지 않은 것들. 우선순위는 "충실도 점수를 실제로 움직이는가" 기준이다.

기능 추가보다 **R1·R4 가 먼저**다. 평가서 [A] §16 의 결론과 같다:
> 정확도 주장을 신뢰할 수 있게 만드는 일이, 기능을 하나 더 붙이는 일보다 가치가 크다.

---

## R1. 네이티브 PDF 객체 추출 경로 ★★★★★

**문제.** 현재는 born-digital PDF 도 200dpi 로 렌더링한 뒤 OCR/CV 로 다시 알아맞힌다.
PDF 안에 이미 텍스트·글꼴·벡터 경로·임베디드 이미지·변환 행렬이 들어 있는데 그것을 버리고 있다.
OCR 오타, 글꼴 추정 오차, 도형 오검출의 상당수가 여기서 나온다.

**방향.**

```
                    PDF
                     │
         ┌───────────┴───────────┐
    네이티브 있음              스캔/이미지형
         │                       │
   pdfio 객체 파서            OCR / CV  (현재 경로)
         └───────────┬───────────┘
                     ↓
              공통 Layout IR   ← extract.py 가 지금 내는 layout JSON 을 확장
                     ↓
                   PPTX
```

- `pdfio.py` 에 `text_objects()`, `image_objects()`, `path_objects()`, `paint_order()` 추가.
  pypdfium2 로 가능한 범위를 먼저 확인하고, 부족하면 `pdfminer.six`(MIT) 같은
  **비-AGPL** 파서를 검토한다. PyMuPDF 는 AGPL 이라 배포본에 넣을 수 없다.
- 페이지 단위로 경로를 고른다: 추출 가능한 텍스트가 충분하면 네이티브, 아니면 현재 OCR 경로.
- layout JSON 요소에 `source_method`("native"|"ocr")와 `confidence` 를 붙여
  어느 경로로 나온 결과인지 보고서에서 구분할 수 있게 한다.

**완료 기준.** born-digital 픽스처에서 텍스트 복원율 ≥ 0.99, 글자 내용이 OCR 오타 없이 일치.

## R2. 원본 paint order 복원 ★★★★☆ (R1 종속)

**문제.** `build.py:336` 이 `{"rect":0,"table":1,"image":2,"line":3,"text":4}` 타입 순서로 쌓는다.
원본이 `이미지 → 도형 → 텍스트 → 이미지 → 선` 순이면 겹침이 어긋난다.
반투명 도형, 이미지 위 텍스트, 콜아웃, 주석이 많은 장표에서 드러난다.

**방향.** R1 의 `paint_order()` 로 얻은 순서를 요소의 `z` 에 그대로 넣는다.
`z` override 가 타입 순서를 이기는 동작은 이미 있고 테스트로 고정돼 있으므로
(`test_explicit_z_override_wins_over_type_order`), 값을 채워 넣는 것이 전부다.
OCR 경로에서는 원본 순서를 알 수 없으므로 타입 순서를 그대로 둔다.

## R3. 원본 임베디드 이미지 추출 ★★★★★

**문제.** `build.py: crop_image()` 가 400dpi 렌더 이미지에서 영역을 잘라내고
텍스트 자리를 인페인팅한다. PDF 안에 3000×2000 JPEG 이 들어 있어도 결과물에는
400dpi 로 리샘플링된 재인코딩본이 들어간다. "편집 가능하게 만들되 원본 이미지를
훼손하지 않는다"는 요구와 정면으로 충돌한다.

**방향.**

1. 임베디드 이미지 원본 바이트를 그대로 꺼내 PPTX 에 넣는다(JPEG 는 재인코딩 없이 통과).
2. 배치는 원본 변환 행렬(CTM)로 계산한다. 종횡비가 안 맞는다고 중앙 크롭으로 단정하지 않는다
   — 비균등 스케일·클리핑 경로·의도적 왜곡을 구분한다.
3. 클리핑을 안전하게 표현할 수 없을 때만 현재의 래스터 크롭으로 폴백하고, 그 사실을 보고서에 남긴다.

**완료 기준.** 이미지 픽셀 해상도가 원본 이상, JPEG 재인코딩 0건, 가장자리 잘림 회귀 테스트 통과.

## R4. PowerPoint COM 검증 게이트 ★★★★★

**문제.** 현재 `quality.validate_package()` 는 zip/XML 구조와 python-pptx 재개봉만 본다.
이것은 ECMA-376 적합성도, PowerPoint 가 복구 경고 없이 여는지도 증명하지 못한다.
`render.py` 는 PowerPoint COM 을 쓰지만 **렌더링 목적**이고, 복구 경고를 감지하지 않는다.

**방향.** Windows 에서 다음을 회귀에 편입한다.

1. PowerPoint 로 연다 → 복구 경고/열기 실패 감지
2. 저장 → 닫기 → 다시 열기
3. PowerPoint 로 PDF 내보내기 → **LibreOffice 가 아닌 PowerPoint 렌더**와 원본 비교
4. 실패 시 종료 코드 7 (`EXIT_POWERPOINT`, 규약은 이미 `quality.py` 에 있고 아직 미사용)

이 게이트가 회귀에 들어가기 전까지 **"PowerPoint 호환"이라고 표기하지 않는다.**

## R5. 텍스트 재구성 정밀화 ★★★☆☆

`extract.py: group_lines()` 는 수직 근접·높이 유사·좌/중앙/우 정렬만 본다. 취약한 경우:

다단 조판 · 자간이 벌어진 제목 · 한영 혼용 · 위/아래 첨자 · 글머리표와 내어쓰기 ·
세로쓰기 · 회전 텍스트 · 조밀한 표 안 텍스트

- 베이스라인을 먼저 복원한 뒤 묶는다.
- 회전 텍스트를 글리프 단위가 아니라 줄/런 단위로 합친다.
- 글꼴 대체 보고서(원본 글꼴 → 실제 사용 글꼴)를 남긴다.

## R6. 표 검출 신뢰도 ★★★☆☆

현재 `tables.py` 는 괘선 기반이라 다음이 약하다: 차트 격자 오인, 괘선 없는 표 누락,
셀 안 서식이 첫 런으로 뭉개짐, 병합 셀이 많은 불규칙 표.

- 검출 신뢰도 점수와 오탐 억제 규칙 추가
- 괘선 있음/없음/부분/병합/중첩/불규칙 픽스처로 행 높이·열 너비·테두리·채움을 각각 비교
- 표가 소유한 텍스트·선이 독립 개체로 중복 생성되지 않는지 확인 (현재 `_owner()` 로직)

---

## R7. 검출 임계값 외부화 ★★★☆☆

품질 임계값은 `quality.DEFAULTS` + `PDF2PPTX_THRESHOLDS` 로 외부화했지만,
**검출** 임계값은 아직 코드 안에 흩어져 있다. 예: `extract.py` 의
`gray < 232`, `a < 1500`, `fill < 0.85`, `std > 26`, `sw/h > 0.117`, `w < 60`.

이 값들은 특정 문서군에 맞춰 조정된 암묵적 가정이며 시간이 지나면 부채가 된다.

```
config/detection.yaml · table.yaml · image.yaml · text.yaml
profiles/corporate_report.yaml · meeting_deck.yaml · scanned_document.yaml
```

문서군별 프로파일을 두면 사내 문서 최적화와 일반성을 분리할 수 있다.

## R8. 저장소 구조 · CI ★★★☆☆

- `src/` 레이아웃으로 이전 (지금은 최상위 평면 모듈)
- `proto_table.py`, `proto_table2.py`, `analyze.py` — 프로토타입 잔재 정리
- GitHub Actions: `pytest` + 빠른 픽스처 시각 검증 (`.github/workflows/ci.yml` 참조)
- `dist/PDF2PPTX.exe` 84MB 가 **git 히스토리에 남아 있다**(`.git` 458MB).
  추적은 해제했지만 히스토리 정리는 별도 결정 — 공개 저장소로 갈 때 `git filter-repo` 검토

## 사내 베타 승인 기준 (평가서 [B] §9)

아래가 전부 참이기 전에는 무인 배치 실행에 쓰지 않는다.

- [x] 깨끗한 환경에서 전체 테스트 통과
- [x] 음성 대조군이 망가진 출력을 실제로 거부
- [x] 품질 미달이 0이 아닌 종료 코드로 끝남
- [x] 품질 미달과 정상 통과가 보고서에서 구분됨 (`pass` / `degraded` / `fail`)
- [ ] 사내 문서 30~50건 코퍼스의 분류별 결과 기록 (`tests/corpus/`)
- [ ] PowerPoint 가 복구 경고 없이 열고, 저장·재개봉·내보내기까지 통과 (**R4**)
- [ ] born-digital 문서에서 네이티브 경로가 동작 (**R1**)
- [ ] 원본 임베디드 이미지가 재인코딩 없이 보존 (**R3**)
